Projection Rules

可见消息层投影

  • routing_delta → 任务调度卡片滚动文本
  • routing_timeout_fallback → 卡片显示“超时，已转 basic_agent”
  • message_delta(source=coordinator_2) → 普通聊天气泡流式显示
  • tool_call_* / observation_added → agent steps UI

行为层投影

  • routing_delta 不直接整段写回给下一轮 agent
  • 而是沉淀成“路由摘要 + 原始 routing transcript 可选引用”
  • coordinator_2 的可见推理可保留，但写回上下文时要有结构化边界
  • 工具执行历史按 action/observation 对保存，保证后续 agent 清晰消费
Special Rule: coordinator_2 Chat Bubble
为什么需要单独事件，而不是继续沿用 thought
如果继续把 coordinator_2 的输出当 agent_step.thought，它会继续被渲染成思考框，而不是普通聊天气泡。
因此 timeline 里必须允许 message_started/message_delta/message_completed 这种“可见消息事件”，并且标明 source=coordinator_2。
这样前端才能把它当成普通 assistant 消息流，而不是 agent 内部步骤。
CLI Rule
高自由度，但服从可读性
CLI 可以选择：1) routing 阶段只打摘要状态；2) coordinator_2 / basic_agent 做节流流式；3) 若依旧过于噪声，则仅输出阶段状态与最终结果。Web UI 则强制保留真实流式。
