Section 4: 行为层上下文精细化管理

目标：用户可以看到全量流式内容，但后续 agent / LLM 不直接吞原始 UI 文本，而是吃经过编译、分层、结构化的 context pack。

Core Principle
Raw Timeline ≠ Next-Turn Context
Raw Timeline
全量事件归档
Behavior Compiler
上下文编译器
Context Pack
给目标 agent 的清洁上下文
Target Agent
coordinator_2 / basic_agent / future agents
下一轮模型输入不应直接等于“用户刚看到的全部文本”。必须经过 behavior compiler，按 agent 角色重组。
Three Storage Tiers

Tier 1: Raw Timeline

保存全量事件：routing delta、message delta、tool call、observation、switch 等。

职责：审计、回放、调试、前端流式来源。

Tier 2: Behavior Records

把 timeline 归纳成结构化行为记录：路由收据、agent handoff、工具账本、未完成事项。

职责：给 context compiler 提供稳定、可压缩、可组合的中间层。

Tier 3: Context Pack

为当前目标 agent 临时编译的上下文包。

职责：真正送入模型，强调当前任务、相关历史、清晰边界。

Behavior Record Types
Route Receipt
decider = coordinator_1
decision = coordinator_2 / basic_agent / future_agent
reason_summary = 结构化路由摘要
raw_transcript_ref = 原始 routing delta 引用
Handoff Record
from = coordinator_2
to = basic_agent
why = “推导后发现需要文件/搜索/浏览器工具”
carry_forward = 要带给下一个 agent 的关键结论
Compilation Rules

必须保留的高价值信息

  • 当前用户目标
  • 最近一次 routing 决策及其摘要
  • 未完成事项
  • 最近一个 agent 的关键结论
  • 工具执行的结构化观察结果

不要直接原样塞回模型的内容

  • 前端装饰文本、滚动文本、扫光 UI 文案
  • 长篇 routing delta 原文全部拼回 transcript 主体
  • 工具原始脏日志整段回灌
  • 多轮里已经解决掉的低价值中间噪音
coordinator_2 Special Rule
Visible Full Stream, Structured Future Recall
对用户：coordinator_2 的全量 reasoning / content 继续完整流式显示。
对未来 agent：不强制吞掉全部原文，而是保留结构化摘要 + 可选 transcript 引用。
这样既不牺牲用户可见性，也不污染后续上下文窗口。
Context Window Strategy
精细化管理，而不是一刀切裁剪
当前 turn：高保真保留
最近未完成 turn：中高保真保留
已解决旧 turn：摘要化保留
工具与切换历史：以 ledger 方式长期保留
