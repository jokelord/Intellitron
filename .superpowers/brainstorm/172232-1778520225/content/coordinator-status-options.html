Coordinator 过渡态组件方向

目标：在本地模型较慢时，让用户明确感知“系统仍在工作”，但前端只显示专业状态，不暴露原始推理文本。

A

路径判定卡

最专业、最稳妥。强调系统正在进行任务归类和执行路径选择。

B

任务调度卡

更偏系统调度语义，突出“正在对接合适执行代理”。

C

意图解析卡

更像“系统理解你要做什么”，亲和一些，但工程感略弱。

Option A
路径判定卡
推荐
正在判定执行路径
Coordinator 正在分析任务复杂度与执行模式
1
识别请求类型与复杂度
2
评估是否可直接回答
3
必要时切换执行代理
适合放在现有蓝色思考框之前，形成“路径判定 → 具体执行”的清晰两段式体验。
建议文案：正在判定执行路径 / 正在切换执行代理 / 已转入执行阶段
Option B
任务调度卡
系统感更强
正在分配执行代理
系统正在选择最合适的处理链路
检查是否需要浏览器 / 文件 / 命令执行能力
验证当前任务是否需要交由执行代理接手
正在建立后续执行上下文
优点是动态感更明显；缺点是“调度”这个词比“判定路径”略抽象。
Option C
意图解析卡
更亲和
正在解析任务意图
系统正在理解你的目标并决定处理方式
I
理解用户目标
II
匹配处理模式
III
进入具体执行
可读性不错，但和现有“思考”框语义更接近，区分度不如 A/B。
