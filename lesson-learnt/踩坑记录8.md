# 踩坑记录 8：Solstice NVFP4 元数据与 FlashInfer planner 兼容

日期：2026-10-03。环境：Jetson Thor；SGLang 0.5.17；FlashInfer Python/Cubin 0.6.17；FlashInfer JIT cache 0.6.17+cu130。

## 1. NVFP4 量化元数据不完整导致启动失败

### 现象

模型启动进入线性层量化方案选择后，`CompressedTensorsConfig._is_static_tensor_w8a8` 访问 `input_quant.num_bits`，报 `AttributeError: 'NoneType' object has no attribute 'num_bits'`。

模型目录为 `~/Project/LLM-weight/Solstice-AI-qwen3.8-27B-NVFP4-Abliterated`。其 `config.json` 的 `quantization_config.config_groups.group_0` 仅记录 `weights: {num_bits: 4}`，缺少权重量化类型、策略、分组大小以及 `input_activations`。仅注明 4 bit 并不能描述 NVFP4 W4A4 格式。

### 根因与证据

`recipe.yaml` 明确声明 `scheme: nvfp4`。只读取 safetensors 文件头、未加载权重数据的审计发现：496 个量化投影均使用 U8 `weight_packed`，输入维度按两个 FP4 值打包为一个字节；FP8 E4M3 `weight_scale` 的形状为 `[输出维度, 输入维度/16]`；`weight_global_scale` 和 `input_global_scale` 均为 F32 标量。GDN、普通 attention 和 MLP 投影均符合这一布局。

用 CPU/meta 上的微型 `Linear` 调用真实安装的 `CompressedTensorsConfig.from_config(...).get_linear_scheme(...)`，可以在不加载模型的情况下重现原始异常。

### 解决方案与边界

先保存原始文件：

`config.json.before-sglang-nvfp4-schema-repair-20261003`

使用当前安装版本的 `compressed_tensors.quantization.preset_name_to_scheme("NVFP4", targets=["Linear"])` 完整方案替换 `group_0`，保留原有 format/targets、ignore 和其他所有顶层元数据。方案包括 4-bit float、对称量化、`tensor_group`、group size 16、静态权重、局部动态输入量化。精确 JSON 对比确认修改仅限 `quantization_config.config_groups.group_0`，未修改 safetensors 数据。

真实方案选择验证 GDN 合并投影、MLP 和 attention 返回 `CompressedTensorsW4A4Fp4`；`lm_head` 和明确忽略的 MTP 原始线性层保持非量化。Target 和 MTP draft 的 `ModelConfig` 均继续为 text-only，hidden size 5120、64 层。

相关加载陷阱：此 checkpoint 使用 `model.language_model.*` 权重前缀。安装版 text wrapper 先移除 `model.`，导致实际 body loader 找不到 `language_model.*`，可能静默跳过权重。CPU 微型模型验证了这一跳过行为；项目自有 `sglang_extensions/qwen3_5_text.py` 只将开头的 `model.language_model.` 规范化为 `model.`，再委托原版 loader。仅此 infer YAML 的 `external_model_package: sglang_extensions` 启用适配器；MTP 继续使用原版 registry 实现。

更早的 text 元数据归一化备份为 `config.json.before-sglang-text-normalization-20261003`，保留不覆盖。

## 2. EAGLE draft-extend 的 FA2 fast planner 少传一个参数

### 现象

启动进入 EAGLE draft extend CUDA graph 路径后，`flashinfer_backend.fast_prefill_plan` 调用 `_cached_module.plan(*args)`，FFI 报需要 20 个参数、实际只有 19 个。

### 根因

安装版 SGLang fast path 的参数列表止于 `num_colocated_ctas`。FlashInfer 0.6.17 正常 FA2 `plan()` 路径还追加 `uniform_q_len=0`，其 C++/FFI binding 的最后一个参数也是 `uniform_q_len`。此异常来自 Python 调用与 FFI 签名不一致，不能通过修改推测步数、草稿量化配置或删除编译缓存解决。

### 解决方案与模型隔离

准备补丁：`patch/sglang-flashinfer-fast-prefill-uniform-q-len.patch`。

仅当进程环境变量 `LLM_DEPLOYMENT_FLASHINFER_PREFILL_UNIFORM_Q_LEN_COMPAT` 严格等于 `1` 时，fast path 在现有列表末尾追加 `0`。未启用时保留原有 19 个参数与原行为。

仅 Solstice infer YAML 设置 `sglang.flashinfer_prefill_uniform_q_len_compat: true`。启动链路为 infer YAML → `scripts/1_A_start_sglang.sh` → 当前 server/worker 进程环境；`backend/config.py` 显式建模此开关。其他模型的配置未添加开关；若 false/null/缺失，启动脚本主动 unset 环境变量，防止父进程残留 `1` 影响其他模型。没有硬编码模型路径或对其他模型默认开启兼容。

用户授权后，先备份安装依赖原文件并确认字节/hash 一致，再以零 fuzz forward 应用补丁。与备份逐字节比较确认源码仅增加上述环境变量条件与 `args.append(0)` 两行，未修改其他包或权重。

- 原文件备份路径：`~/Project/LLM-deployment/.sglang/lib/python3.12/site-packages/sglang/srt/layers/attention/flashinfer_backend.py.before-llm-deployment-uniform-q-len-20261003.bak`。
- 原文件/备份 SHA-256：`3cb0b4d5c4d3e8e94724d07c91130ab69d85e73c84cefaf3f69a5ad7813f5c7e`。

### 验证范围

`tests/test_sglang_flashinfer_patch.py` 将补丁以零 fuzz 应用到临时副本，确认安装依赖字节未改变；安装完成后测试也能在临时副本反向恢复原始函数再验证，测试本身不写入依赖。
